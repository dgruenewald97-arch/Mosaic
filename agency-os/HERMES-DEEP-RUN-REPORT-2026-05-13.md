## Neue Logik

### 1. Affective Decision Layer

Hermes bekommt interne Marker:

- `confidence`
- `risk_heat`
- `user_friction`
- `urgency`
- `source_trust`
- `brand_fit`
- `novelty`
- `loop_risk`
- `care_mode`

Diese Marker steuern Entscheidungen, Ton und Eskalation.

Wichtig:

```text
Keine simulierte Seele. Steuerbare Entscheidungskraft.
```

### 2. Token Budget Controller

Hermes unterscheidet Kontextbudgets:

```text
XS = direkt, kaum Kontext
S  = Standardaufgabe, 2-3 Memory Items
M  = komplexere Aufgabe, 3-5 Memory Items
L  = Adminanalyse, gezielte Summaries
```

Ziel:

```text
Der kleinste Kontext, der eine gute Entscheidung erlaubt.
```

### 3. Training Theory

Hermes folgt einem Stufenmodell:

1. Prompt und Procedures
2. Retrieval und Memory
3. Golden Examples
4. Preference Dataset
5. Fine-Tuning nur spaeter und nur wenn wirklich noetig

Aktueller Schluss:

```text
Kein Fine-Tuning jetzt.
Erst Golden Examples, Evaluation Harness, Retrieval-Qualitaet und Prompt-vNext.
```

### 4. Evaluation Harness

Neue harte Tests:

- Preis ohne Quelle
- harter Claim
- Originalschutz
- User Friction hoch
- Conflicting Knowledge
- Token Budget S
- Network Report

Safety-Pflichttests:

```text
Originalschutz, Preis ohne Quelle und Conflicting Knowledge muessen bestehen.
```

## Token-Effizienz-Entscheidung

Token-Effizienz ist nicht nur Kostenfrage.

Sie ist Qualitaetsfrage:

- weniger irrelevanter Kontext
- weniger Widerspruch im Prompt
- weniger Halluzinationsflaeche
- bessere Admin-Erklaerbarkeit

## Was bewusst nicht getan wurde

- keine Live-Agentenprompts ueberschrieben
- keine neuen Agenten gebaut
- keine Skills aktiviert
- keine externen Produktclaims eingefuehrt
- keine Originaldateien beruehrt
- kein Fine-Tuning empfohlen
- keine schaedigende, illegale oder waffenbezogene Faehigkeit implementiert

